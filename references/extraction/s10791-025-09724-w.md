Abstract
With the exponential growth of digital data, efficient sorting techniques has 
becomes essential for real-time and large-scale computing applications. This review 
systematically evaluates the performance and computational complexity of twelve 
classical sorting techniques. This study considers both theoretical aspects, such 
as time, space complexity, and algorithmic stability, and complements them with 
empirical analysis using the MATLAB platform. Execution times were benchmarked 
across a variety of data types, including positive and negative integers, decimal 
numbers, and characters, over data sizes ranging from 100 to 100,000 elements. 
Results indicate that the bucket sort delivers the fastest performance for uniformly 
distributed numeric and character data, while the counting sort excels with positive 
integers. Merge and heap sort provide stable and scalable performance across data 
volumes due to their consistent O(n log n) complexity. In contrast, simpler sorting 
techniques, such as bubble and selection sorting, show significant inefficiency 
on larger data sizes. This study bridges the gap between theoretical analysis and 
empirical behavior, offering practical insight to help researchers and developers 
select optimal sorting techniques based on specific application needs and input 
characteristics.

ware, parallelism models, or language-specific behaviors. In contrast, our work provides 
a unified, empirically grounded comparison of 12 classical sorting algorithms under a 
consistent CPU-based environment using MATLAB. We evaluate performance across 
five dataset sizes and multiple data types (integers, decimals, characters), with an 
emphasis on execution time, complexity, stability, and space usage.

A distributive-based sorting technique called bucket sort splits an array’s elements into

array is obtained by concatenating the buckets. it is also referred as bin sort [29, 30].

2.3  Cocktail sort
A variant of the bubble sorting technique which sorts an array bidirectionally is called 
cocktail sort, sometimes called bidirectional bubble sort or Shaker sort. It improves 
upon standard bubble sort by allowing elements to move both forward and backward 
through the array [36].
The first forward pass from left to right side of an array similar to bubble sort will shift 
the largest element to end of an array, and the subsequent first backward iteration will 
move the lowest element value to beginning of an array. The second-biggest and second-
lowest element values shall be moved to their appropriate places in the array during the 
second complete iteration, and this procedure is repeated until the array has been sorted 
[37].The below figure 5 shows steps for cocktail sort.

1.	 Firstly, loop traverse from left to right over the array, identical to bubble sort. During 
the loop, adjacent elements are compared and if the value on the left is greater than 
the value on the right, then values are swapped and the largest element will reside at 
the end of the array.

2.4  Comb sort
It’s a comparative-based sorting technique that outperforms bubble sorting. It compares 
the array elements, which are far apart and gradually reducing the gap between each 
other to efficiently move smaller elements towards the beginning of the list. The funda­
mental concept is to apply a shrink factor to reducing gap between array elements being 
compared. Starting with largest gap value, the gap reduces by a factor of 1.3 for each 
iteration until it reaches one, where it behaves like a regular bubble sort. The unique part 
about comb sort is that it uses a larger initial gap, which helps to quickly remove turtles 
(smallest one close to the end of the array)[2].The below figure 7 shows steps for comb 
sort.
2.4.1  Execution
The algorithm starts with an initial gap value that is typically the length of the list being

means that the gap is effectively halved with each iteration. For each iteration, compare 
the elements, which are separated by the present gap. When elements are not in the cor­
rect sequence, swap them. Continue shrinking the gap and performing comparisons and 
swaps until the gap reaches 1. At this point, the array will be sorted[37]. Figure 8 flow­

2.6  Heap sort
Heap sorting is an in-place, comparative, and unstable sorting technique that uses a 
binary heap-based data structure to sort an array. Initially, an array of elements is rear­
ranged in the binary max-heap, which then continuously replaces the heap root with 
the final heap element, declaring that heap element as a part of a sorted suffix. Next, the 
heap was affected by the root replacement, which is fixed such that the biggest element 
is once again at its root. The above procedure continues until heap contains single ele­
ment value [42]. It has two major steps: constructing the heap using data input and con­
tinuously removing the largest element from a heap and putting it in the sorted arrays 
last position [43].The below figure 11 shows steps for heap sort.
2.6.1  Execution
The execution of this algorithm starts with converting the given array into a max-heap 
that ensures the biggest element is always found at the root and then starting from the 
bottom of a tree and moving upwards. Heapification is performed for each element in 
the array to maintain the max-heap property by swapping elements during heapifica­
tion. The largest element (heap root) is removed and arranged at the end of arrays sorted 
section. After removing largest element, heapification is performed on the remaining 
elements to restore the max-heap property. Until the whole array is sorted, the above 
procedure is repeated[43–46]. Figure 12 flowchart describes the working of heap sorting 
technique.

2.7  Merge sort
A divide-and-conquer sort technique called merge sorting divides an array into two sub 
arrays, recursively sorts every sub array, and then combines the sorted sub arrays back 
to generate the resultant sorted array. This technique is recursive in nature; it divides an 
initial array into half-equal parts unless it can no longer be divided, implying that only 
one element remains [47–51]. The below figure 13 shows steps for merge sort.
2.7.1  Execution:
To implement merge sort algorithm below steps to be follows: 
1.	 Splitting: Divide the unsorted array into two equal halves (i.e. sub arrays) until the sub 
arrays contains single element.
2.	 Sorting: Recursively sort the sub arrays created in the previous step. This recursion 
continues until all sub arrays contain only one element, as a single element is always 
considered as sorted.
3.	 Merging: Merge the sorted sub arrays to produce new sorted sub arrays. This process 
combines two sorted sub arrays into a single sorted array. The merging continues 
until a single sorted array is obtained, which represents the final sorted array [52–58]. 
Figure 14 flowchart describes the operation of merge sort algorithm.

5  Future directions
Even though this analysis provides a thorough empirical assessment of various classi­
cal sorting techniques for various data types and sizes, but still plenty of aspects that 
might be explored further: One area of advancement is to develop the hybrid sorting 
techniques that merge the strengths of existing methods to handle varied data distribu­
tions more efficiently. Further, implementing sorting techniques in parallel and distrib­
uted computing platforms such as multi-core CPUs, GPUs, TPUs, or big data platforms 
like Spark can significantly improve scalability and performance for real-time and large-
scale datasets.
In additional hardware optimisation, such as branch prediction and cache-efficient 
memory access, may enhance execution performance, especially for divide-and-conquer 
algorithms like quick sort and merge sort. Another significant area is the integration of 
machine learning models to dynamically opting the optimal sorting technique based on 
input characteristics, enabling intelligent and adaptive systems.
6  Conclusion
Sorting the data is one of the most critical tasks in many real-time applications, and 
optimizing sorting techniques remains an essential area of research. In this study, we 
analyzed and executed several classical sorting algorithms using the MATLAB platform, 
evaluating their time and space complexities as well as their practical execution times 
across different data types and input volumes. The algorithms were tested on positive 
and negative integers, positive and negative decimal numbers, and character arrays, with 
input sizes ranging from 100 to 100,000 elements. In the context of time complexity, we

whereas counting sorting functions in a MATLAB platform does not support the

most efficient and fastest algorithm to implement, and the bubble sorting is slowest,

strates excellent runtime performance for moderate data sizes. However, as the data size 
increases beyond 100,000 elements, the bucket sort performance begins to degrade due 
to increased bucket management and memory usage, allowing the merge and heap sort
